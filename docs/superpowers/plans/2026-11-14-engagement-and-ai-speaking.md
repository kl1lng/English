# План: удержание пользователей и ИИ-говорение для 30english

Дата: 2026-11-14. Статус: **черновик на согласование. Код не менялся, ничего не запушено и не задеплоено.**

Старый план `2026-10-26-student-pilot.md` относится к школьному пилоту (ученики, учитель, Neon). Для текущего приложения для взрослых он не действует. Этот документ его заменяет.

## 0. Цель и принципы

**Цель.** Сделать так, чтобы взрослые возвращались в приложение каждый день и реально говорили по-английски. Сегодня есть 30 уроков, запись ответа с письменным отзывом и озвучка слов. Нет повторения слов, нет причин вернуться завтра и нет живого диалога.

**Принципы.**
1. Один небольшой, проверяемый шаг за раз. Каждая фаза даёт пользу сама по себе.
2. Новые данные кладём в отдельные таблицы Supabase, а не в JSON-поле `profiles.data` (причины в разделе 2).
3. Платные и ограниченные ИИ-вызовы только за проверкой входа и дневной квотой на сервере.
4. Всё, что можно проверить тестом (расписание повторов, серия, значки), живёт в чистых модулях `src/lib/` с тестами.
5. Ничего не пушим, не деплоим и не меняем в Supabase/Vercel без вашей явной просьбы. SQL-миграции я пишу файлами, запускаете их вы.
6. Не вводим оценку произношения, баллы IELTS и «проценты беглости». Текущие правила проекта это запрещают, и модель этого не измеряет.

**Не цели (anti-goals).** Школьный пилот, кабинет учителя, детские аккаунты, платная подписка, оценка произношения, хранение аудио.

## 2. Архитектурные решения

**Ветка.** Вся работа в `feature/engagement` от `main`. Каждая фаза в своих коммитах. Влить или откатить решаете вы.

**Новые данные в отдельных таблицах, не в `profiles.data`.**
Причины: (а) `profiles.data` перезаписывается целиком, и два устройства затирают друг друга; (б) массив `submissions` с транскриптами растёт без предела; (в) повторы слов пишутся часто, и перезапись всего блоба на каждый ответ расточительна. Существующий блоб не трогаем (кроме малой чистки в Фазе 0).

**Проверка входа на сервере.** Новый модуль `server/auth.js`: берёт заголовок `Authorization: Bearer <jwt>`, создаёт клиент `@supabase/supabase-js` и вызывает `auth.getUser(jwt)`. Документация Supabase прямо говорит, что `getUser(jwt)` проверяет токен запросом к серверу Auth и подходит для авторизации на сервере (на клиенте `getSession` для этого не годится). Использует уже существующие переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Новых секретов не нужно. Лежит в `server/`, а не в `api/`, чтобы Vercel не принял его за отдельную функцию (как `server/cloudflare-ai.js`).

**Квоты на сервере.** Таблица `usage_counters (user_id, kind, day, count)` и SQL-функция `bump_usage(kind, limit)` (security definer), которая атомарно увеличивает счётчик и возвращает «можно / нельзя». Заменяет `Map` в памяти. Лимиты по умолчанию: отзыв по записи 30/день, диалог 5 сессий/день, чат 60 сообщений/день. Значения меняются через переменные окружения.

**Расписание повторов: библиотека `ts-fsrs`** (алгоритм FSRS). По документации: `createEmptyCard()`, `fsrs().next(card, now, Rating.Good)` возвращает `{ card, log }`. Поля карточки для хранения: `due, stability, difficulty, scheduled_days, learning_steps, reps, lapses, state, last_review` (`elapsed_days` помечено как устаревшее, не храним). Рейтинги 1–4: Again, Hard, Good, Easy. **Перед установкой** пакет проходит навык `vet-before-install` (правило из ваших настроек).

**Тесты: Vitest.** Добавляется как dev-зависимость (тоже через `vet-before-install`), скрипт `npm test`. Покрываем только чистую логику, интерфейс проверяем руками в браузере.

**Структура кода.** `main.jsx` не раздуваем. Новое живёт в:
```
src/lib/        чистая логика с тестами: srs.js, cloze.js, streak.js, xp.js, badges.js, time.js
src/data/       scenarios.js (сценарии диалогов)
src/components/ Review.jsx, ReviewCard.jsx, Dialogue.jsx, BadgeToast.jsx, ...
src/hooks/      useWordCards.js, useGamification.js (работа с Supabase)
server/         auth.js, usage.js, dialogue.js
api/            dialogue.js, (cron) remind.js
supabase/migrations/  001_..., 002_... (по одному файлу на фазу)
```
В `main.jsx` меняются только точки подключения: навигация, виджет на дашборде, вызов `recordActivity` после урока.

**Мягкое отключение.** Если миграция ещё не выполнена, экран нового функционала показывает «Раздел ещё не настроен» вместо ошибки, и остальное приложение работает как раньше. Это же позволяет вливать фазы по одной.

**Цвета и стиль.** Только токены/CSS-переменные, без новых hex в компонентах. Если нужен новый оттенок (например, для «серии в огне»), он добавляется токеном в `:root`. Иконки из `lucide-react` (уже в проекте), без эмодзи вместо иконок. Анимации только `transform`/`opacity` с `prefers-reduced-motion`. Вид в одном стиле с текущими карточками (казахстанская тема уроков).

### Фаза 1. Повторение слов (SRS) (≈4–5 сессий). Зависит от 0.1, 0.2

**Что получает пользователь.** Раздел «Повторение»: каждый день короткая сессия (по умолчанию 10 карточек) со словами из пройденных уроков. Забытые слова возвращаются чаще, выученные реже. На дашборде виджет «К повторению: N слов».

**Правила.**
- Слово попадает в колоду **при завершении урока** (когда выполнена минимальная длительность): все 6 слов урока. Уникальный ключ слова — `word_key`, поэтому 21 повторяющееся слово (например, `preserve` в 4 уроках) создаётся один раз.
- Существующие пользователи: при первой загрузке нового раздела колода достраивается по уже завершённым урокам (`insert ... on conflict do nothing`). Операция идемпотентна.
- Лимиты: не более 20 новых карточек и 100 повторов в день. Размер сессии 10 (кнопка «Ещё 10»).
- Карточка «к повторению», если `due <= now`. Порядок: просроченные раньше, затем новые.
- Расписание: `fsrs({ request_retention: 0.9, enable_fuzz: true })`. Параметры по умолчанию, оптимизация по `review_log` возможна позже.

**Типы упражнений** (по очереди, чтобы не наскучило):
1. **Flip.** Показано английское слово и кнопка 🔊 (`speakWord`). Пользователь вспоминает значение, жмёт «Показать» и видит `kk`, `ru`, пример. Затем сам оценивает: Забыл / Трудно / Хорошо / Легко (4 кнопки → рейтинги 1–4).
2. **Cloze.** Пример из урока с пропуском слова + 4 варианта (3 отвлекающих слова из того же урока). Оценка автоматическая: ошибка → Again; верно с первой попытки → Good; верно быстрее 4 секунд → Easy.
3. **Listen** (добавляется в Фазе 4, когда готов общий каркас упражнений).

### Фаза 2. Привычка: XP, значки, цели, заморозка серии, напоминания (≈4–5 сессий). Зависит от 0.2, 0.3, 1.x

**Правила (чистые функции в `src/lib/xp.js`, `badges.js`).**
- XP: первый зачёт урока +50; повторная попытка +10 (не более одной в день); карточка Good/Easy +2, Hard/Again +1 (не более 100 XP/день за повторы); новый день серии +5×min(серия, 7).
- Уровни по порогам XP (например, 0 / 100 / 250 / 500 / 900 / 1400 …), показываются на дашборде рядом с серией.
- **Заморозка серии:** +1 за каждые 7 дней серии, максимум 2 в запасе. Автоматически тратится, если пропущен ровно один день. Логика в `streak.js` (покрыта тестами: пропуск 1 день с заморозкой — серия сохранена; пропуск 2 дней — сброс; заморозка не тратится зря).
- **Дневная цель** (выбор пользователя): «только урок» или «урок + 10 повторов». Прогресс цели показывается кольцом на дашборде.
- **Значки** (стартовый набор из ~12): первая запись; 3, 7, 30 дней серии; 10 и 100 выученных слов; 5, 15, 30 уроков; первая сессия повторения; первый диалог (после Фазы 3); сертификат. Описаны в одном массиве `badges.js` с функцией-предикатом от статистики. При получении показывается уведомление.

**Открытые решения владельца** (по умолчанию беру первый вариант):
1. Что считать днём серии? **Рекомендую: урок ИЛИ 10 повторов.** Альтернатива: только урок (строже, но проще потерять серию).
2. Канал напоминаний (см. 2.7).

### Фаза 3. Диалог с ИИ-собеседником (≈6–8 сессий). Зависит от Фазы 0 (вход и квоты)

**Что получает пользователь.** Раздел «Разговор»: выбирает сценарий (например, «Встретить гостя в аэропорту Астаны»), ИИ-собеседник говорит первую фразу, пользователь отвечает голосом, ИИ отвечает ему в ответ. 4–6 реплик, затем итог: что получилось, до трёх исправлений, три полезные фразы с кнопкой «Добавить в повторение».

**Поток одной реплики.**
```
Браузер: запись (≤ 45 с) + { scenarioId, история последних реплик (текст), номер реплики, согласие }
  → POST /api/dialogue (multipart)
      1. requireUser (JWT) → consume(userId, 'dialogue_turn')
      2. Whisper: транскрипт реплики (общая функция transcribe(), вынесенная из cloudflare-ai.js)
      3. LLM (Groq, JSON): { reply, recast, hint, endSession }
      4. ответ: { transcript, reply, recast?, hint? }
Браузер: показывает транскрипт и ответ, озвучивает ответ
```
- Аудио не сохраняется (как сейчас).
- История приходит от клиента, но обрезается на сервере (не более 8 реплик, не более 400 символов каждая). Транскрипты считаются **недоверенными данными**, а не инструкциями (как в существующем промпте отзыва). Системный промпт задаёт роль, уровень B1–B2, ответ не длиннее ~40 слов и один встречный вопрос. Неточность пользователя ИИ мягко «переформулирует» в своём ответе (recast), без лекций. Нельзя оценивать произношение.
- Промпт-инъекции: роль и правила только в системном сообщении; ответ валидируется как JSON; длины ограничены; ссылки и код из ответа отбрасываются.
- Согласие: перед первой репликой сессии то же подтверждение, что и для записи ответа («Отправить запись на обработку ИИ»).
- Квота по умолчанию: 5 сессий/день и 30 реплик/день на пользователя; аварийный выключатель `AI_DIALOGUE_ENABLED=false` (переменная окружения Vercel, добавляете вы).

**Озвучка ответа ИИ (TTS).** Старт с `speechSynthesis` браузера (бесплатно, уже используется как запасной вариант). В ходе спайка (3.1) сравнить с серверным голосом Cloudflare Workers AI. **Доступность и цену модели нужно проверить перед обязательством**, пока этого факта у меня нет. Выбор голоса: спросить вас по итогам прослушивания.

**Сценарии.** `src/data/scenarios.js`, 8–10 штук: аэропорт Астаны; отель в Алматы; заказ бешбармака; дорога на Шымбулак; экскурсовод в Туркестане; такси; рынок/сувениры; знакомство с принимающей семьёй. Поля: `id, title, aiRole, userGoal, opening, targetWords[], unlockAfterLesson, level`. `targetWords` берутся из слов соответствующих уроков, чтобы диалог закреплял словарь и результат шёл в SRS.

**Итог сессии.** Один вызов LLM на всю беседу (текст, без аудио): сильные стороны, до трёх исправлений (с проверкой, что цитата реально была в транскрипте, как в `parseFeedback`), три фразы. Сохраняется в `dialogue_sessions.summary`. Тексты реплик не сохраняются. Фразы по кнопке попадают в `word_cards` с `source='custom'`.

**Задачи.**

## 6. Проверка и безопасность

**Для каждой фазы до слов «готово».**
1. `npm test` и `npm run build` без ошибок.
2. `preview_start`: пройти новый сценарий руками, консоль без ошибок.
3. Скриншоты на 390 px и ~1440 px, нет горизонтального скролла, видимый фокус, контраст ≥ 4.5:1, `prefers-reduced-motion`.
4. Проверка RLS: второй аккаунт не видит чужие `word_cards`, `player_stats`, `dialogue_sessions` и не может их изменить.
5. Для API: запрос без токена, с чужим токеном, с превышением квоты.
6. Перед слиянием: навык `superpowers:requesting-code-review`.
7. Отчёт о том, что проверено, а что нет.

**Секреты.** Новых секретов в Фазах 0–1 нет. В Фазе 2 (Telegram) и Фазе 3 (выключатель, лимиты) потребуются переменные окружения: их вносите вы в Vercel и `.env`, я значения не вижу и в чат не печатаю. Имена добавляются в `.env.example`.

**Приватность.** Аудио не хранится. Тексты диалогов не хранятся, только итог. Транскрипты отзывов по урокам хранятся как сейчас (в профиле). Нужен простой способ «удалить мои данные» (отдельная задача после Фазы 3, так как удаляет все новые таблицы каскадом по `user_id`).

**Расходы.** Квоты на пользователя, глобальный выключатель диалога, лимиты длины записи и ответа. Бесплатные лимиты Groq и Cloudflare могут закончиться при росте числа пользователей, поэтому до публичного продвижения нужно проверить фактические лимиты и тарифы (я их сейчас не проверял).

## 7. Деплой и откат

- Работа в ветке `feature/engagement`. Пуш в `main` вызывает продакшен-деплой Vercel, поэтому **пушить и вливать буду только по вашей явной просьбе**. Для пуша есть ключ деплоя из `PROJECT_MAP.md`.
- Миграции аддитивные (новые таблицы), старые данные не меняются. Откат кода: вернуть ветку. Откат базы: отдельные `drop table` по каждой фазе (описываются в комментариях миграции, но не выполняются без вашей просьбы).
- Supabase на бесплатном плане: при паузе проекта `discover-kazakhstan` новые разделы тоже не работают (как и вход).
